    1. The problem a circular queue solves

    A queue is first in, first out: people join at the back and leave from the front. With a plain array, every time you dequeue, the front slot becomes empty and useless. You either shift every item left (slow, O(n)) or keep moving the front forward and slowly run out of room even though the start of the array is empty.

    2. The idea

    Pretend the last slot of the array is connected to the first, forming a ring. When a pointer walks off the end, it simply continues at slot 0. Freed slots get reused, and nothing ever has to be shifted.

    3. Three variables run everything

    • front: index of the oldest item, the one that leaves next.
    • rear: index of the newest item, the last one that joined.
    • count: how many items are stored right now.

    We start with front = 0, rear = N - 1, count = 0. Rear begins one step behind front so that the first enqueue (rear + 1) lands exactly on slot 0.

    4. The one trick: modulo

    To move a pointer one step around the ring, use (index + 1) % N. For N = 5: 2 becomes 3, 3 becomes 4, and 4 becomes (4 + 1) % 5 = 0. That wrap from the end back to the start is the whole “circular” part.

    5. The two operations

    Enqueue (add)

    1. If count == N, the queue is full: overflow, stop.
    2. Move rear: rear = (rear + 1) % N.
    3. Store the value at data[rear].
    4. count++.

    Dequeue (remove)

    1. If count == 0, the queue is empty: underflow, stop.
    2. Read the value at data[front].
    3. Move front: front = (front + 1) % N.
    4. count--, then return the value.

    6. Full or empty? Why we keep count

    When the ring is completely full and when it is completely empty, front and rear end up in the same relative position, so the pointers alone can’t tell the two apart. Keeping count removes the doubt: empty is count == 0, full is count == N. (The other common fix is to always leave one slot unused, which wastes space.)

    8. The code

    Python

    class CircularQueue:
    def __init__(self, n):
        self.n = n
        self.data = [None] * n
        self.front = 0
        self.rear = n - 1
        self.count = 0

    def enqueue(self, x):
        if self.count == self.n:
            raise OverflowError("queue is full")
        self.rear = (self.rear + 1) % self.n
        self.data[self.rear] = x
        self.count += 1

    def dequeue(self):
        if self.count == 0:
            raise IndexError("queue is empty")
        x = self.data[self.front]
        self.data[self.front] = None
        self.front = (self.front + 1) % self.n
        self.count -= 1
        return x

    def peek(self):
        if self.count == 0:
            raise IndexError("queue is empty")
        return self.data[self.front]

    C

    #define N 5
int data[N], front = 0, rear = N - 1, count = 0;

int enqueue(int x) {
    if (count == N) return 0;      /* overflow */
    rear = (rear + 1) % N;
    data[rear] = x;
    count++;
    return 1;
}

int dequeue(int *out) {
    if (count == 0) return 0;      /* underflow */
    *out = data[front];
    front = (front + 1) % N;
    count--;
    return 1;
}

    9. Cost and uses

    Every operation is O(1): a couple of comparisons and one modulo, no shifting. Memory is fixed at O(N). Circular queues appear in round-robin CPU scheduling, keyboard and network buffers, audio streaming and print spoolers, anywhere a fixed-size buffer is read and written continuously.

    10. Explanation with scenario:

    “Imagine a round table with N seats and a waiter. People sit down at the rear and get served from the front. When someone is served, their seat frees up. Instead of everyone shuffling along, the table is a circle, so when the rear reaches the last seat, the next person just takes seat 0. Mathematically that’s (index + 1) % N. I also keep a counter so I always know if the table is empty or full.”

    Questions people ask:

    • Why modulo? It turns “one past the end” back into 0 with a single expression.
    • Why start rear at N − 1? So the first enqueue’s (rear + 1) % N gives slot 0.
    • Why not just compare front and rear? They look identical when full and when empty; count disambiguates.
    • Does dequeue erase the value? Not necessarily. Real code often leaves the old value and just ignores it, since count and front say it no longer counts. The lab clears it so you can see it go.
